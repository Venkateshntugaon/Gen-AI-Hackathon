# Challenges and Solutions

## Phase 0
- **Python 3.11 not available.** The plan asks for Python 3.11, but the dev machine has only 3.13 and 3.14. We used Python 3.13 for the venv, because CPU PyTorch and all listed packages publish wheels for it. If the team prefers 3.11, install it and recreate `.venv`.
- **Gemini model retired.** `check_setup.py` failed with 404: *"models/gemini-2.5-flash is no longer available to new users. Please use models/gemini-3.8-flash."* The script's model-list fallback showed the options; the team chose `gemini-3.8-flash` and we updated `.env`, `.env.example`, the config default and the README.
- **`.env.example` renamed instead of copied.** During setup `.env.example` was renamed to `.env`, which removed the example file from the repo. We recreated it with placeholder values only. Use `cp`, not `mv`.

## Phase 2
- **Options split across lines.** The first parser version only recognised an option line if it started with "A)", so "B) …" on its own line was glued onto the previous option. Fix: the parser remembers how many options the current question already has and expects the next letter (B after A). Caught by the unit tests.
- **Letters inside option text.** "Vitamin C." could look like a new option "C.". Fix: option markers must appear in order (A, B, C, D) and lower-case "a." is not accepted as a marker.
- **Merged DOCX table cells** are returned by python-docx once per grid column; we skip repeated neighbouring cell text.
- **gemini-3.8-flash temporarily unavailable (503 "high demand").** The fallback was verified with `gemini-3.5-flash` for one run. On a messy paper using roman-numeral options (i, ii, iii), Gemini kept the numerals in the option text (as told: copy verbatim) and an answer written as "iii" was dropped because it is not a letter A–D, so the teacher picks it. Safe behaviour; noted in case the prompt needs refining later.
- **Switched to gemini-3.5-flash.** gemini-3.8-flash kept returning 503 "high demand". The team chose `gemini-3.5-flash` (reviewing one MCQ is a light task) and updated `.env`, `.env.example`, the config default and the README.

## Phase 3
- **Free-tier limit of 5 requests per minute.** The first detection run stopped at question 9 with 429 RESOURCE_EXHAUSTED. The 2/4/8 s retry then raised our friendly "Gemini is busy … press Retry" message, as designed. Because every reply is cached on disk, a rerun a minute later only made the missing calls. A full review of a paper (judge + generate + verify per question) will regularly hit this limit.
- **LLM judge over-flagged "implausible".** In the first run Gemini gave plausibility ≤ 2 to reasonable distractors ("Cardiovascular system" for the urinary-system question, "Ice" for heating water), which buried the real flaws. We made the 1–5 scale explicit in prompts/judge.md with examples ("rate how tempting it is, not how wrong"). After that Q3 was clean and "Ice" was no longer flagged; a few debatable flags remain (e.g. "Survival" for extinction).
- **Embedding similarity on single technical words.** MiniLM scored "Stigma" vs "Stamen" at only 0.14, below SIM_TOO_FAR (0.20), so similarity flagged it as implausible although it is a good distractor (the LLM did not agree). Short scientific terms embed poorly. The threshold is kept as planned; the merged finding shows "detected by: similarity" only, so the teacher can see that only the weakest layer raised it.

## Phase 4
- **Free-tier daily limit: 20 requests per day for gemini-3.5-flash.** The first full-pipeline run stopped at question 4 with 429 "Generate content requests per day limit exceeded … retry in 23h25m". A 10-question paper needs about 25–30 calls (judge, generate, verify per question, plus retries). Our retry first treated this like a per-minute limit and waited for nothing. Fixes: (1) `llm.py` now detects "per day" limits and stops at once with a clear message telling the teacher to try tomorrow or change GEMINI_MODEL; (2) for per-minute limits it waits as long as Gemini suggests ("retry in N s", capped at 65 s) instead of only 2/4/8 s; (3) for development we switched `.env` to `gemini-3.5-flash-lite`, which has its own quota. The disk cache means nothing already answered is ever asked again.
- **Duplicates got no suggestions.** The plan generates replacements only for high/medium findings, but duplicates are rated low, so the planted duplicate in the sample paper got no replacement. We now also send duplicates for replacement.
- **Retries must ask for something new.** Replies are cached by prompt, so a plain retry would return the same cached (rejected) candidates. The retry prompt therefore lists the rejected candidates ("do not repeat them"), which changes the prompt and gives genuinely new candidates.

## Phase 5–6
- **Blank cells in the Confirm table.** Rows a teacher adds in `st.data_editor` hold `NaN`, and `str(NaN)` is the text "nan", which would count as an option. Fix: a `cell()` helper treats None/NaN as empty.
- **Deprecated Streamlit argument.** `use_container_width` prints a deprecation warning in Streamlit 1.67; we switched to `width="stretch"`.
- **Invalid button icon.** Streamlit only accepts real emoji or `:material/...:` icons; "↺" crashed the Results page in our automated test. We use Material icons.
- **Teachers do not use CSV/JSON.** After trying the app, the team pointed out that teachers cannot read CSV or JSON files. We added a Word "Review Report" next to the revised paper; CSV/JSON moved under "For analysis". Word's "Save as PDF" covers PDF needs without a new library.
- **Restarting the app from a script killed the script.** `pkill -f "streamlit run app.py"` also matched the shell command running it. Use `pkill -f "[s]treamlit run app.py"` (the bracket stops the pattern matching itself).

## Phase 7
- **Evaluation and app competing for quota.** The evaluation (~90 Gemini calls) and the live app share the same per-minute quota and the same cache file. Running both at once risks one process overwriting the other's cache entries. We run them one after another; the cache makes an interrupted evaluation resume where it stopped.
- **The judge over-flagged "implausible" (precision 0.14).** In the first evaluation, 58 distractors were flagged implausible for 8 planted ones; 44 of the false flags came from the LLM judge alone (plausibility ≤ 2). Re-scoring the cached judge replies offline showed that counting only plausibility = 1 as MEDIUM keeps recall at 1.00 and doubles precision (0.14 → 0.30), while also requiring the LLM's own "implausible" label barely helped (0.17). We now map plausibility 1 → MEDIUM and 2 → LOW, so the teacher still sees it but no replacement is generated. This also saves Gemini calls.
- **Direct Gemini calls without retry.** The paraphrase step of the evaluation called Gemini directly and crashed on a 503. Both helper scripts now use `llm.generate_text()`, which has the same retry logic as the pipeline.

## Phase 8 (found while running the test cases)
- **Same suggestion for two options.** In TC5, the first generation round and the retry each picked "10 °C" for a different option, because the retry did not know the first round's picks. The runner now skips retry candidates that match a suggestion already chosen.
- **Option labels inside extracted options.** For a scanned PDF, Gemini copied "A) Oxygen" verbatim (as the prompt says). `strip_option_letters()` removes only a label that matches the option's own position, so text like "A bicycle" is kept.
- **The extractor had no retry.** A 503 "high demand" crashed the scanned-PDF extraction. The extractor now goes through `llm.generate_text()`, the same retry used everywhere else.

## Review of the 10-question test paper (PS84_test_paper_10_flawed_MCQs.pdf)
The team ran a 10-question paper with planted flaws through the app and read the generated review_report.docx. Seven problems were found and fixed:
1. **Grammar cue missed with a blank ("…called an ________.").** `_` counts as a word character, so the last "word" was the underscores, not "an". Fix: strip trailing blanks, underscores, dots and similar before checking for "a"/"an". Q5 is now flagged.
2. **"All of the above" as the answer produced six bogus findings.** Similarity said "Solar"/"Hydropower" were unrelated to the answer text "All of the above", and the LLM said every option was "also correct" (which is exactly why "All of the above" is right). Fix: when the answer is "All/None of the above", skip the similarity checks and ignore LLM also_correct verdicts on the other options.
3. **Embeddings cannot compare numbers.** "50 °C" vs "100 °C" scored 0.91 and was flagged "also correct". Fix: `is_mainly_number()` (digits, optional units, or number words), and the too-close/too-far checks are skipped when the answer or the option is mainly a number.
4. **Suggestions despite a doubtful answer key.** In Q8 (key "Ag" for gold), the generator proposed replacing "Au", the actually correct option. Fix: if a question has a possible_wrong_answer_key finding, no suggestions are generated; the card and report say "Resolve the answer key first".
5. **LLM "answer give-away" findings that made no sense.** The judge labelled "Carbon dioxide" an answer cue because it is a common misconception (a good distractor!). Fix: answer_cue comes from the rules only; the LLM creates an option finding only for is_also_correct yes/partly or plausibility ≤ 2 (its issue_type label is not used).
6. **Several findings on one option.** "O2" showed both "Also correct" and "Duplicate" with the same reason. Fix: after merging, each option keeps one finding: the highest severity, with ties broken by issue type (also_correct > duplicate > implausible > …).
7. **0-based indices in reasons.** A reason said "option 0 (Iron)" while the paper shows Iron as B. Fix: the judge prompt now lists each option with its paper letter and asks for letters only; any leftover "option N" / "distractor N" is rewritten to the letter. The UI passes each question's answer position so the letters match the paper.
